# S1：Swift 版 A1 皮，網頁↔Swift 對照

2026-11-25。Swift 沒編譯過（Windows，沒有 swift／clang／metal 編譯器）。網頁行號是寫這份時 W1 正在改的 `prototype/web/index.html`，W1 收尾後可能位移幾行；來源是 `patches/F2-網格聯集遮罩-對HEAD-v2.60.diff` 的 `JELX.mode=9`。Swift 行號是 `ios/NieNie/Slime/`。

## 1. 要 S2 在 SlimeRig.swift 做的事（不做的話 skinU 1 也走舊外框，畫面跟 build 158 一樣）

加在 `SlimeRig.swift` 檔尾（同一個檔才碰得到 private）。只讀，不動物理。

```swift
/// v2.61 A1: what the mesh skin reads (JellySkin.swift, SkinMeshSource). Read only.
extension SlimeRig: SkinMeshSource {
    var skinTri: [Int] { TRI }
    var skinEdg: [Int] { EDG }
    var skinRest: (x: [Double], y: [Double]) { (Q0X, Q0Y) }
    var skinWalls: (l: Double, r: Double, b: Double) { let w = worldWalls; return (w.l, w.r, w.b) }
}
```

- 粒子位置用現成的 `labParticles()`，外框順序用 `bnd`，畫面換算用 `toScreen`、`drawZ`，都不用加。
- `TRI`、`EDG` 維持「整個換掉、不逐格改」（現在 `buildMesh` 就是這樣）。皮靠陣列有沒有換來判斷要不要重做索引。
- `SlimeView.swift:120` 用 `(rig as AnyObject) as? SkinMeshSource` 接，S2 加上 extension 之後不用再改 SlimeView。

### 兩邊不一樣的地方

1. 剪裁：網頁用算好的皮（模糊後的邊）剪；手機用路徑剪，路徑＝外框＋翻面的三角形（同方向繞兩圈，nonzero 一定蓋到）＋外框邊的保底線。邊比皮尖一點，跟 v2.60 一樣。翻面 0、沒有細處時就是原來那條外框路徑。
2. 氣泡：網頁 v2.61 也剪，手機照舊不剪（預設 0 顆）。
3. 手機的模糊和打光沒有裁切區（F2 的第 3 條，這批沒做）。

## 3. 每幀的量

- 三角形：芋圓 955（517 顆粒子），補點後 937 到 950；補點上限是三倍顆數。
- 畫圖次數：遮罩那趟 1 次三角形＋有細處時 1 次膠囊（黏條、第二團開著各多 1 次）；模糊 4、打光 1 跟以前一樣。少了 CPU 填遮罩和整張上傳。
- 膠囊：平常 0 條，量到最多 391 條（放手那格）；全部的邊 1471 條是上限。
- 貼圖：遮罩 393×852 單色 8 位元一張（GPU 私有），四倍取樣那張只在晶片內（模擬器改成一般私有）。模糊 196×426、49×106 不變。
- 緩衝：頂點、膠囊各三份輪流，號誌 3 擋住還沒畫完的；夠大之後不再配置。索引只在補點、重建時重做一份。CPU 暫存只會變大。

## 4. 驗了什麼

- **數值對照**：`S1-遮罩對照.py` 把網頁當下的粒子、三角形、牆倒出來，用 `SkinMesh.update` 的算式逐行轉寫（單精度）重算，再用同樣規則軟體畫一張，跟網頁 WebGL 的遮罩比。17 格（靜止、兩指拉三組、亂刷兩組、放手）：
  - 頂點差 0、縮進後差最大 0.00006 點、厚度倍數差 0、膠囊條數每格都一樣（0、58、64、66、209、391）。
  - 遮罩平均差 0.0002 到 0.0004（滿分 1），**差超過 0.3 的像素 17 格都是 0**。樣張 `S1-遮罩對照.png`（左：重算、中：網頁、右：差）。
  - 剪裁路徑：皮有、路徑沒蓋到的像素最多 99（皮 32002），只用舊外框的話最多 221；多蓋的 0。
- 這只證明算式一樣，**不證明 Swift、Metal 編得過**。
- 靜態查：大括號、小括號、中括號四個檔都成對；`litMask.path =`、`drawJelly(`、`JellySkin.render(` 的呼叫點各只有一處，都接上；`jelMesh*`、`jelCap*` 四個名字跟 `makeFunction` 的字串一致、沒跟 `WindowScene.metal` 撞名；頂點 buffer 0、1，片段沒用 buffer，索引獨立，沒有重複；`SkinMesh.Cap` 兩個 SIMD4（32 位元組）對 `CapIn` 兩個 float4，`SIMD2<Float>` 8 位元組對 `float2`；遮罩列 0 在上（頂點 `1 - y*u.y`，取樣 uv 往下），跟 CG 遮罩同向；r8Unorm 沒有色彩空間轉換。
- 舊路（skinU 0）：同樣的 CG 填色搬進 `paint()`，`bodyMask` 就是原來的 `mask`，剪裁用 `body`，順序不變。沒有在手機上量畫面差。

## 5. 沒驗到

編譯、真機畫面、GPU 時間、低電量掉不掉幀、模擬器的四倍取樣、剪裁路徑在翻面很多時的 Core Animation 時間（翻面 600 個就多 600 個小三角形）。
