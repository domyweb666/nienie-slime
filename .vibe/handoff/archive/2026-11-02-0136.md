### 環境與設定（不變的事實，沿用上份）

- 多米沒有 Mac。編譯走 GitHub Actions，裝機走 TestFlight；build 號＝run number
- `swiftui-port` 有 Swift＋web＋docs；`main` 只放 web＋docs（Pages 自動發布）。推 main 用暫存 worktree：`git worktree add <scratchpad>/wt-main origin/main -B main-sync`，`git cherry-pick -n <commit>`，`git checkout HEAD -- ios`，確認 `git diff --cached --quiet <commit> -- prototype .uiux CLAUDE.md` 一致後 `git commit -C <commit>`、push 到 main，再移除 worktree 與分支
- 發 TestFlight：等 push 觸發的編譯過（`gh run watch <id> --exit-status` 放背景），再 `gh workflow run ios.yml --repo domyweb666/nienie-slime --ref swiftui-port -f testflight=true`
- selftest：launch.json 的 web-proto（伺服器根目錄就是 `prototype/web`，網址 `http://localhost:8765/`），手機尺寸 375×812。33 項一輪約 50 秒，頁面跑的時候不回應；用 setTimeout 連跑 4 輪、結果放 `window.__runs`，分次讀，每次讀不要 await 超過 40 秒。重新整理後等 3.5 秒再排程（讓開場跑完）。跑測試時別插入其他會改狀態的除錯程式，會污染那一輪
- 瀏覽器面板藏著時 rAF 會停，手動驅動用 `window.requestAnimationFrame=()=>0` 再自己呼叫 `update(1/60)`；截圖前先 `draw()`，zoom 前先 screenshot 一次
- 測試裡模擬手指一律用累加位移：`螢幕位置 += (世界目標 − 手指現在的世界位置) × 鏡頭倍率`。T33 第一版用世界換螢幕，鏡頭在動，手指退回來
- 用 python 改 JS 原型時，取代字串裡的註解一律放在整段新程式最後；套用後檢查「// v2.xx」後面同一行還有沒有程式（這次犯了兩次）
