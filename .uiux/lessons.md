# lessons｜捏捏史萊姆 UIUX

| 日期 | skill | 發生什麼 | 下次規則 |
|---|---|---|---|
| 2026-10-31 | feel | 技術選型檔還寫著「Swift＋Rive」，但 CLAUDE.md 與程式早已改成純 Swift 程序化 rig，兩份文件打架一整個會話沒人發現 | 每次定案寫進 CLAUDE.md 時，同步回寫 `.uiux/` 對應檔；開場讀檔若兩邊不同，以較新的為準並當場改舊的 |
| 2026-10-31 | feel | 多米口頭用「數位減壓寵物」「塑形」描述產品，但核心動作卡的不做清單寫「寵物行為不做」、手感模式定在混合模式 C。詞跟定案有落差 | 多米換用新詞描述產品時，先對照核心動作卡，把落差列成表請他選，不直接照新詞開工 |
| 2026-10-31 | feel | 多米在網頁版第一次捏就發現描邊打結、回彈不順、合成音難聽，Agent 之前在檔案裡寫「做得到、已實作、永遠不壞」全是看程式推的，沒摸過 | 「做得到」只能在有人摸過之後寫；沒摸過的一律寫「程式裡有這段邏輯，未驗證」。多米自測不能過閘，但可以當 bug 回報與方向否決 |
| 2026-10-31 | feel | 「永遠不壞」的限制寫在單點上（每點徑向、切向上限），沒有守相鄰點的關係，所以還是會交叉 | 形狀不壞的保證要寫在點與點的關係上（順序、距離、面積），或改用數學上不可能交叉的模型（形狀匹配、隱式曲面） |
| 2026-10-31 | feel／VibeRails | Verlet 積分裡，「改位置」就是「加速度」。慢搖、回正用改位置寫，等於每小步都推一把，240 步每秒累積成轉飛；抖一下的衝量也少除 240 倍 | 表演用的位移（呼吸、搖、浮）位置與前一幀一起搬，不留速度；彈簧類（回家、回正）要嘛走速度加阻尼，要嘛做純運動學；所有「每小步」的量先想清楚單位 |
| 2026-10-31 | feel／VibeRails | 線性形狀匹配（beta>0、面積正規化）在重疊小區塊＋Verlet 下能量正回饋，放手後自己越拉越長；書上的「穩定」是指 beta<1 單一區塊 | 剛體區塊（beta=0）＋全域面積壓力就能做到壓扁鼓兩側，不要開線性項 |
| 2026-10-31 | feel／VibeRails | 細的突起（尖端寬度小於粒子間距）一定自交；用角度等距取邊界會取不到細觸手 | 任何突起的最小寬度 ≥ 1.2 倍粒子間距；邊界用弧長等距取樣；每次改外形都掃一輪亂數種子量自交 |
| 2026-10-31 | VibeRails | 兩個「拉回去」的目標如果基準不同（一個每幀置中、一個沒置中），交界會被一點一點拉開，症狀出現在幾十幀後、位置在兩群粒子的交界 | 所有「參考座標」用同一個基準（零均值）；看到「交界處慢慢壞」先查基準 |
| 2026-10-31 | VibeRails | 連續六輪憑直覺猜原因全錯（彎、飄、互不穿透、繩子、密度） | 症狀跟多個改動同時出現時，不要猜：每次只回退一項做成對照檔，一輪跑完就知道 |
| 2026-10-31 | VibeRails | 粒子互不穿透若跨群作用（不同觸手、觸手對身體），被手指拉過去的部分會卡住永遠解不開 | 互不穿透只在「不該變形的群內」用；跨群允許交疊，交給形狀匹配拉回原排列 |
| 2026-10-31 | feel | Agent 用程式模擬手指的自測可以抓「壞掉」（自交、爆炸、面積漂移），但抓不到「好不好捏」 | 程式自測只當回歸測試（不壞），手感判斷一律真機＋新的手 |
| 2026-10-31 | feel／CI | TestFlight 第一次上傳跑了 7 次 run 才過：Issuer ID 貼成 7 字元、App Store Connect 沒建 App、API 金鑰是 Developer 角色（export 回 Cloud signing permission error）、Bundle ID 建成別的名字、workflow 檔只在非預設分支（手動觸發 422）。每個錯都要等一到兩分鐘 archive 才看得到 | 簽名前先用金鑰直接打 ASC API：檢查三個值的格式、列出金鑰看得到的 App、對照 project.yml 的 Bundle ID，有錯在 10 秒內報出來；workflow_dispatch 的檔要在預設分支上才能手動觸發；Secrets 名稱以使用者實際取的為準，改 workflow 配合比請他重設快 |
| 2026-10-31 | feel | v2 重寫演算法、再移植 Swift，參數表上的「接觸點先凹」「偶發特別回彈」都沒搬過去；「黏滯延遲」表上 0.06、程式 0.12。兩版推上 main、多米摸過、Swift 編譯過，一路沒人拿參數表逐列對過程式 | 每次換演算法或移植，拿參數表逐列對程式，列出「表有程式沒有」「表與程式數值不同」兩張清單寫進手感測試紀錄；對不上的先補或改表，再推 |
| 2026-11-01 | feel／CI | 觸發 TestFlight 上傳（workflow_dispatch）之後又推了一個 docs commit 到同一分支，workflow 的 concurrency 設 cancel-in-progress，上傳 run #26 被新 push 的編譯 run 取消，要重新觸發 | 要上傳 TestFlight 時，先把該推的全部推完、等編譯過，再觸發 dispatch；觸發後到上傳完成之前不推同一分支 |
