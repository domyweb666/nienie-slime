# 手機版移植批次（暫定，2026-11-07 晚上）

> 給多米點頭用。點了頭才動 Swift，一次一批，每批 push 一次給 GitHub Actions 編譯，TestFlight 累積三批才發一次。
> 來源：多米 11-07 定案「走路是主機制，搖留著當捏以外的另一種互動」；網頁版 v2.31 跟 Swift 版 v2.27 逐段對過。

## 兩邊現在差在哪

Swift 版（`ios/NieNie/`）做到網頁的 v2.27：形狀匹配、黏土、活物感、印象、聲音、眼睛、睡著、節奏、心情變色、觸手互撞都有。之後網頁又走了五版，手機一版都沒跟：

| 網頁版本 | 做了什麼 | 手機版 |
|---|---|---|
| v2.28 | 果凍皮、切換列、窗台和碗、重力、白天夜晚背景 | 沒有，還是平塗懸空 |
| v2.29 | 黏液取消、三角網防打結、眼睛不出界 | 黏液只是預設關，程式還在；防打結沒有 |
| v2.30 | 爬進爬出碗、爬窗框、跨出窗外、打翻擺飾 | 沒有 |
| 走路 | 面板假裝步數、牠從窗外帶東西回來、捏掉、放滿擠掉 | 只有面板一顆「讀步數」的按鈕（StepProbe） |
| v2.31 | 皮定 A、碗回中間、只跟碗互動、擺飾當背景、搖晃沉澱、散出來吃回來 | 沒有 |

另外兩個預設跑掉了：網頁現在是圓身、有眼睛；Swift 預設還是 v2.27 的「8 條觸手、沒眼睛」。

## 原則

只搬網頁上**預設打開**的東西。網頁留著當對照、面板才開得了的（爬窗框、窗外、擺飾剛體、推擺飾、B 皮切換），手機不搬。程式少一半，真機要驗的也少一半。

每批動完，手感基準不准退步：黃金行為 1 到 16 在 TestFlight 上重玩一遍。這台電腦編譯不了 Swift，寫錯只有 Actions 的編譯會抓，跑起來對不對要等你裝。

## 批次

### 批次 0：預設對齊（小，半天）

把 Swift 的預設改成跟網頁一樣：眼睛開、圓身（limbs 0、觸手互撞關）、黏液整段刪掉（`drops`、`dropsV`、水滴和絲的繪圖、咕嚕）。

你怎麼驗：TestFlight 開起來跟網頁藍底長得一樣（圓的、兩顆眼睛、猛扯不掉水滴）。黃金行為 1 到 16。

### 批次 1：防打結、眼睛不出界（v2.29）

搬六件：靜止形狀切三角網，每個三角形面積不能小於靜止的一成五，翻不過去就打不了結；抓著時身體轉得動；整團被拖有速度上限；手指實心；畫面邊是軟的，可以超出去一點再回來；眼距有上限、臉最多歪 50 度。

你怎麼驗：標準清單 v2.29 那節，除了「坐在碗裡」那條。黃金行為 14、15。

風險：每小步多一層三角形檢查。要在最舊的 iPhone 開低電量模式亂拉，看面板的每幀毫秒數有沒有掉幀。

### 批次 2：窗台、碗、背景（v2.28 窗台＋v2.31 碗在中間）

搬：重力、窗台、碗在正中間、落地壓扁、碗上方放手掉進碗、其他地方掉回窗台、鏡頭固定不跟、白天和夜晚兩張背景、石頭盤和盆栽畫在窗台兩端（只是圖，沒有物理）。四張 webp 直接進 bundle。藍底還是懸空，一條行為都不動。

要你決定的小事：手機版「藍、白天、夜晚」放哪裡切。網頁是上方切換列；手機我建議放進面板，畫面上不多一排按鈕，預設白天。

你怎麼驗：標準清單 v2.28 窗台那節，扣掉「跳上窗戶、黏窗、黏液」三條；v2.31 的前三條。

### 批次 3：爬出碗、爬回碗（v2.30 只搬碗）

只搬一條路線：牠在碗裡想出來，伸偽足、爬上碗口、翻過前緣流到窗台上；在窗台走一走；爬上前緣再流進去。碗前緣蓋住下半身。窗框、窗外、擺飾剛體、推擺飾都不搬，網頁也是關的。

你怎麼驗：v2.31 第二、三條（放著幾分鐘牠只爬出碗、走窗台、爬回碗）。

### 批次 4：走路（原生，主機制）

這批是重點，也是手機才做得到的：用 CMPedometer 讀真步數（StepProbe 已經會讀，直接接上）。流程照網頁：第一次打開什麼都沒有；第二次打開碗旁邊多一顆石頭，點石頭才問「要讓牠知道你走了多少路嗎」，按「先不要」石頭留著不再問；走 500 步帶一件小的、3000 步帶一件大的；一天最多三件；東西黏在牠身上，捏一下掉在窗台上碗的左右，放著 20 秒自己掉；窗台六格放滿，新的來最舊的淡出。存在 UserDefaults。

回家那趟牠從窗外翻過碗後緣進碗，所以要搬一小段 v2.30 的窗外層和換層，只給這趟用。

兩件要先知道的：build 106 面板的「讀步數」能讀到幾天前？CMPedometer 只給最近七天，你一天沒開 app 隔天還補得到，一週沒開就補不到了。這個數字決定「補幾天」怎麼寫。另一件是你今天提的「運動多牠就比較興奮」，這批先不做，列在下面待設計。

你怎麼驗：標準清單走路那節八條，面板「假裝 800 步」「假裝 3500 步」也要留著方便你測；真步數要帶著手機走一天再看。

### 批次 5：搖晃沉澱（副互動）

CoreMotion 讀加速度扣掉重力，超過門檻算搖一下，原生不用問權限，搖的那一下配輕震。搬：肚子裡的亮粉（150 顆，只畫在身體裡）、濁度、搖三下就滿、約 30 秒沉澱、沉澱時閉眼慢呼吸不出門、清透那一刻發光睜眼叮一聲、堆在碗口（小堆、星星、愛心）、捏著會攪起一點。叮先用程式合成，跟網頁一樣。

果凍皮還沒搬之前，「變霧」用平塗的身體色往奶白混代替，看得出濁和清就好。

要你決定的：散出來吃回來要不要搬。我建議先不搬，網頁留著給你玩；搖現在是副互動，兩種玩法都搬是兩倍的工，而且吃回來那趟牠會爬出碗去窗台撿，跟走路帶回來的東西擠在同一條窗台上。

你怎麼驗：v2.31 第四到第十條。門檻 13 會不會誤觸、霧夠不夠濃、30 秒太不太久，這三件只有真機知道，面板留 shakeG、settleT 給你調。

### 批次 6：果凍皮（v2.28 預覽＋v2.31 皮 A、濁了往 B 混）

網頁的皮是 WebGL2 的著色器（約一萬字元的程式），Swift 現在是 CAShapeLayer 平塗，這批不是搬，是重寫。三條路：

- 甲、Metal 著色器照網頁重寫。畫出來一樣，工最大，最舊機要量掉幀。
- 乙、用 CAGradientLayer 加遮罩拼一個近似：亮弧、邊緣厚一點、內部透一點。跟網頁不會一模一樣。
- 丙、先不做，平塗先上，等前面五批在真機穩了再回來做甲。

我建議丙，最後再做甲。皮是畫面，先把物理和場景搬過去讓你在真機捏到，皮放最後。

## 順序與發 TestFlight 的點

0 → 1 → 2 → 3 → 4 → 5 → 6。走路排在搖前面，因為你定了走路是主機制。

TestFlight 只發一次：七批全做完再發（多米 11-07 晚上定的）。中間每批只靠 Actions 的編譯檢查，跑起來對不對要等最後那一版一起看。

多米 11-07 晚上：順序照上面、吃回來先不搬、皮放最後，開工。

## 待設計（不在這七批裡）

- 運動多牠就比較興奮：今天走得多，牠精神好、愛走、愛來找你；走得少就是平常的牠。基準線永遠是平常的樣子，走路只往上加，不能走得少就難過或生病。要先寫提案，定「多少步算多」和「興奮長什麼樣」再做。
- 走路帶回來的東西會被牠走過去蓋住，要不要另外找位置。
