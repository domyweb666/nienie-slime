# 原型規格（暫定）｜捏捏史萊姆 × Rive

> 2026-10-31。核心動作卡尚未過閘門 1，本規格為暫定版。
> 交給 VibeRails 實作時，附上 參數表-暫定.md 與詞彙表。

## 範圍

- **一個畫面、一個動作：捏。** 不做導覽、儲存、分頁、圖鑑、付費頁、拍照、寵物行為、臉。
- 視覺：2D 平塗卡通、粗描邊、一層色塊陰影、一塊白色亮光，單色即可。不用精修美術，好看會讓人對手感變寬容。
- **延遲、動畫、觸覺、聲音必須是真的**，不能用假資料或模擬器。

## 分工：Rive 畫形狀，Swift 管手感

| 層 | 誰負責 | 內容 |
|---|---|---|
| 外形與變形骨架 | Rive（多米在 Rive 編輯器裡做） | 一條封閉的史萊姆外框、綁在骨架上的網格，以及一組可以被數字推動的骨頭 |
| 觸控、彈簧、塑形記憶 | Swift | 讀手指，算出每根骨頭該在哪，用彈簧接住放手的速度，記住被揉出來的形狀 |
| 觸覺與聲音 | Swift（Core Haptics、音訊） | 和變形來自同一個事件，同一幀觸發 |

這樣分的理由：手感的數字全部集中在 Swift，可以用調整面板即時調；Rive 只負責「被推成什麼樣子」，多米可以自己在編輯器裡把變形畫到滿意。

## Rive 檔要做的骨架（多米在 Rive 裡做）

1. **身體**：一條封閉向量外框（沿用網頁原型的水滴造型，頭頂小尖角），轉成網格，周邊約 20 個頂點，內部幾個頂點。
2. **骨頭**：中心 1 根；周邊 8 根放射狀骨頭（上、右上、右、右下、下、左下、左、左上）；頭頂尖角 1 根。網格頂點綁到最近的 2 到 3 根骨頭，權重平滑過渡。
3. **讓外部數字推動骨頭**：每根周邊骨頭開兩個數字（x 位移、y 位移），中心骨頭開三個（擠壓、拉伸、傾斜）。這些數字由 Swift 每一幀寫入。
4. **色塊陰影與亮光**：陰影是同形狀往右下偏移的色塊；亮光是一個白色橢圓，綁在左上骨頭，跟著變形。

> 待查證：Rive 的網格、骨頭綁定，以及「用 runtime 寫入數字去推動骨頭」的做法（目前是資料綁定／View Model；舊的 Input 已標示淘汰），實作前先對照 Rive 官方文件與 iOS runtime 版本。Rive 也有 Luau 腳本，若彈簧可以直接寫在 Rive 裡，可作為第二方案，但觸覺仍要在 Swift。

## 手勢對應（Swift 計算）

| 手勢 | 史萊姆的反應 |
|---|---|
| 碰到 | 第一幀接觸點先凹（立刻，不能等） |
| 按住不動 | 從接觸點往下沉，兩側鼓出，連續觸覺跟著變飽滿 |
| 從邊緣往外拖 | 最近的周邊骨頭跟著手指，左右各帶動 2 根，越遠越弱；根部變細 |
| 從外面往內推 | 最近的周邊骨頭被推進去，對面鼓出 |
| 放手 | 用彈簧接住放手當下的速度彈回；若超過定型門檻，部分形狀留下來 |
| 動畫中途再碰 | 從當下位置和速度接手，不能跳回原位（動畫可中斷） |

## 2-4 七條（必須做到）

1. 第一幀立刻動：接觸點先凹。
2. 物理計算不擋畫面更新。
3. 放手速度交給彈簧，不用固定時長的動畫。
4. 動畫可中斷，從當下位置和速度接手。
5. 觸覺分兩種：連續型（強度跟變形量）、事件型（放手那一下）。
6. 畫面、聲音、觸覺從同一個事件觸發。
7. 尊重系統設定：減少動態時換成溫和版本（不是關掉回饋）、系統觸覺關閉時不震、靜音時不響。

## 隱藏調整面板

- 參數表裡每個參數一條滑桿，邊捏邊調，旁邊顯示數值，可一鍵複製。
- 觸發方式：書的例子是三指點兩下，但系統有三指手勢，**選定前先查證會不會衝突**。

## 其他規格

- 互動區離螢幕上下邊緣留距離，不跟回到主畫面、通知中心的系統手勢搶。
- 單指替代：點一下＝壓扁、單指拖曳＝拉長。VoiceOver 自訂動作：捏一下、拉長、揉圓。原型可以先只留介面。
