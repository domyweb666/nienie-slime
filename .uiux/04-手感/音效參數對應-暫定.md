# 音效參數對應｜聲音怎麼跟著手走

> 2026-11-01 v2 分層版。音效檔由 `prototype/sfx-design/design_sfx.py` 產生；播放邏輯網頁版在 `prototype/web/sfx/engine.js`、Swift 版在 `ios/NieNie/Feedback/SlimeAudio.swift`。**這張表、engine.js、SlimeAudio.swift 三處的數字要一起改。**
> 試聽：`prototype/web/sfx/listen.html`（有力道滑桿、可以拖的拉絲板）。

## 原則

1. **聲音跟著物理參數走，不是觸發一段音檔。** 力道、拉伸量、拉伸速度、揉的速度決定每一層的音量、音高（播放速度）、亮度（低通）。
2. **分層，各層獨立隨機。** 按、放手各三層，每層獨立挑一段、獨立浮音高 ±8%。6×6×6 段再乘音高，不會聽到兩次一樣的。
3. **克制。** 揉最小、按中等、放手最響。點綴層（air、settle、strand）在發聲數滿時先丟。
4. **為手機喇叭設計。** 喇叭 300 Hz 以下幾乎出不來，「噗」的份量用缺基音做（只做 2 到 6 倍諧波，耳朵自己補出低音高）。`design_sfx.py --preview` 會印每層 300 Hz 以上的能量佔比，低於 0.6 標 ⚠。v2 全部在 0.77 以上。
5. **延遲。** 所有音檔啟動時解碼進記憶體；Swift 要求 5 毫秒 IO 緩衝（面板讀數看實際值）。

## 素材（65 段）

| 類別 | 層 | 段數 | 是什麼 |
|---|---|---|---|
| press 按 | body | 6 | 肉體感的「噗」，聽起來 130 到 200 Hz 往下掉 |
| | wet | 6 | 被擠壓的濕聲，共鳴從 1.4 kHz 往 450 Hz 滑 |
| | air | 6 | 被擠出去的一顆氣泡 |
| release 放手 | air | 8 | 主角「啵」，大顆到小顆四種輪流 |
| | wet | 6 | 拍回自己的濕拍，共鳴往上開 |
| | body | 5 | 彈回去的份量 |
| pull 拉 | loop | 2 | 連續黏絲底噪，2 秒無縫循環 |

| rub 揉 | loop | 3 | 咕啾咕啾，3 秒無縫循環 |

| | hiss | 3 | 壓久放開、空氣回填的小嘶 |

## 對應表

符號：`i` 按的力道 0..1；`s` 放手強度 0..1 ＝（放手 gain − 0.35）÷ 0.65，gain 本身是「甩多快」與「拉多遠」取大；`st` 拉最長那根抓的手指的拉伸（半徑）；`v` st 的變化速度（半徑／秒，平滑 60 毫秒）；`n` 揉的程度 ÷ 揉的音量上限。音高欄是播放速度倍率，另外每次再浮 ±8%。

### 按 press(i)

i 的來源：抓下去 0.7、從外面推進來 0.5、黏連 0.25、兩指捏 0.6 到 0.9、按鈕 0.5／0.7。Swift 再乘接觸面積：指尖（約 18 pt）×0.8，指腹（約 42 pt）×1.2（面板「按的音量跟接觸面積」0.5 時；0 關）。

| 層 | 響不響 | 音量 | 音高 | 低通 |
|---|---|---|---|---|
| body | i > 0.3 | 0.9 × i^1.2 | 1.06 − 0.14i（越重越低） | 2.6 kHz |
| wet | 都響 | 0.45 + 0.45i | 1 | 1.6 + 3.4i kHz（輕按悶） |
| air | 機率 0.35 + 0.6i | 0.25 + 0.45i | 0.9 到 1.15 隨機 | 6 kHz；晚 15 到 45 毫秒才放 |

同一類 60 毫秒內再觸發：只放 wet，音量 ×0.6。按下去會清掉上一次放手還沒冒完的餘韻。

### 放手 release(s)

| 層 | 響不響 | 音量 | 音高 | 低通 |
|---|---|---|---|---|
| air「啵」 | 都響 | 0.55 + 0.45s | 1.08 − 0.14s（越用力越大顆越低） | 7 kHz |
| wet | 都響 | 0.25 + 0.6s | 1 | 1.8 + 4.2s kHz |
| body | s > 0.2 | 0.85 × s^1.3 | 1.05 − 0.1s | 2.4 kHz |

v1 是「越用力音高越高」（1 + 0.1s），v2 反過來：大力放手＝大顆的啵＝比較低，輕輕放＝小顆清脆。

### 餘韻（放手後）

| 條件 | 聲音 | 數量與時間 | 音量 |
|---|---|---|---|
| 這次抓住拉到 ≥ 0.4R | settle.bubble | round(1 + 2s) 顆，每顆 70% 機率，放手後 0.12 到 0.7 秒隨機 | (0.12 到 0.22) + 0.15s，音高 0.85 到 1.35 |
| 沒拉（< 0.4R）、抓了 ≥ 0.5 秒 | settle.hiss | 60% 機率一聲，晚 30 毫秒 | 0.35 + 0.35s |

都乘面板「放手餘韻」（預設 1，0 關）。

### 拉（每幀）

| 量 | 公式 | 意思 |
|---|---|---|
| 開始算拉 | st > 0.2 | |
| loop 音量 | 拉絲音量上限 × [0.12 × clamp((st − 0.2)/0.4) + 0.88 × min(1, v/2.5)] | 拉的速度決定大小聲，拉著不動只剩一點點張力聲 |
| loop 起落 | 上升 50 毫秒、下降 120 毫秒 | |
| loop 音高 | 0.85 + 0.4 × tanh(st/3) | 越拉越細、越高；7R 時約 1.24 |
| loop 低通 | 1 + 3.5 × tanh(st/3) kHz | 越拉越亮 |
| 細絲密度 | st > 0.4 時每秒 (2 + 16 tanh(st/3)) × (0.25 + 0.75 min(1, v/2.5)) 根 | 越長越密，停手變稀 |
| 細絲 | 音量 0.12 到 0.3，音高 (0.85 + 0.5 tanh(st/3)) × 0.92 到 1.08 | |
| 段落細絲 | 每拉長 0.4R（原本的 pull 事件）固定一根，音量 × (0.6 + 0.8 × 事件 gain) | 觸覺的小震也在這裡 |

拉絲音量上限預設 0.6（面板「拉絲音量上限」）。

### 揉（每幀）

| 量 | 公式 |
|---|---|
| 音量 | 揉的程度（手指速度 ÷ 5R/秒，上限 1）× 揉的音量上限 × 讓位係數 |
| 讓位係數 | clamp(1 − (st − 0.3)/0.7)：拉到 1R 以上就完全交給拉絲聲 |
| 音高 | 0.94 + 0.12n |
| 低通 | 1.4 + 2.6n kHz |

### 發聲數

一次性聲音同時最多 14 個；滿了先丟點綴層（air、settle、strand），主體層（body、wet、放手的 air）照放，Swift 必要時搶最快播完的那個。loop 各自一個聲部，不算在內。

## 觸覺（已經在 Swift，這次沒動）

連續震動跟變形量、放手啵跟放手強度、揉的質地微震、拉段落小震，跟聲音同一個事件、同一幀。手機喇叭吃不到的低頻份量，靠觸覺補。

## 怎麼改

- 某一層的音色不好聽：改 `design_sfx.py` 那一層的函式重跑（會同時寫網頁與 iOS 兩邊、清掉舊檔）。
- 跟手的反應不對（太大聲、不夠高、太密）：改這張表，同步改 `engine.js` 的 `MAP` 與 `SlimeAudio.swift` 開頭那一段。
- 想換回真錄音：檔案照 `<類別>-<層>-NN` 命名丟進兩個資料夾、改 manifest；或用舊的平坦格式 `{"press":[...]}`，兩邊播放程式都還吃（整包當一層）。
